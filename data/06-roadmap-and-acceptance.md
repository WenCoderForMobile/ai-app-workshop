# 里程碑与验收

实现须先改本目录文档，再改代码。当前开发原型只覆盖流程前半（需求确认），完整闭环按下列里程碑补齐。

## 1. MVP 范围

**包含：** 可行性与替代建议、Proposal + Mockup、确认门禁、无意见有界修订、带意见 revise、生成/编译/签名/下发、端侧 11 层验证与插件加载、断云、多插件共存。

**不包含：** DEX/APK 热加载、相机/支付/任意网络、公网多租户、通用 Android 工程生成。

## 2. 里程碑

| 阶段 | 内容 | 出口 |
|------|------|------|
| **M0** | Golden `.apkg`、Schema、签名向量、端侧静态验证 | 无模型也能拒坏包、装好包 |
| **M1** | 固定 Runtime、功能列表、自动加载 | 好包可跑，两 Runtime 轨迹一致 |
| **M2** | 预览确认 + 云侧生成编译发布 + 端侧加载 | 「喝水打卡」类需求走完全流程 |
| **M3** | 越界建议、断云、弱网续传、多插件、失败保留旧版 | 断网可开已装本地插件 |
| **M4** | （可选）独立 Validation Service、KMS、多实例 | 生产审计与故障演练 |

## 3. 当前原型（开发切片，不是目标架构）

已在 `code/` 落地、用于联调意图理解和受限插件闭环，**不替代 M0–M2 的云侧 Task API 与生产级 `.apkg`**：

- 手机 Demo：需求描述、语音输入、连接/发送。
- 电脑 Agent：产品经理分析并确认意图；确认后由程序 Agent 调用 Codex CLI 生成
  不可信 ProgramIR 候选，经过本地确定性编译和 smoke 后写出版本化 `.apkg`。
- 制品镜像：`phone_agent/data/plugins/<programId>/<versionId>.apkg`；开发期控制面经
  TCP 17890 下发带大小和双摘要的描述符，手机再从独立的 HTTP 17891 制品面流式
  下载。控制帧不再承载整包 Base64。
- 手机把下载写入 `.part` 并校验传输摘要后，才在私有插件仓执行验证、staging、
  smoke 与原子激活；成功或失败通过 `artifact_report` 回传，固定 Runtime 只解释
  已验证 JSON，不执行 CLI 生成的 Android 代码。
- 传输：USB `adb reverse` 到本机双端口，支持控制连接断开后重新接入并重放最新任务；
  LLM 只在电脑侧（Ollama 或 DeepSeek 等）。Debug 可使用受限的回环 HTTP，Release
  仍必须使用 HTTPS。
- **仍未做：** 正式 Task HTTP API、Download Ticket、COSE/ES256/KMS、11 层生产
  验证、弱网续传和跨端参考 Runtime。当前无签名开发包只允许 Debug 宿主安装，
  Release 必须拒绝。

目标形态仍是：手机只访云侧 Agent HTTP API，不把 USB 调试当作发布通道。

## 4. 验收用例

| 编号 | 期望 |
|------|------|
| A1 | 端侧访问 `/health`，提交任务 |
| A2 | 可实现需求：分析 → 方案/效果图 → 确认 → 下发 → 验证 → 插件可运行 |
| A3 | `revise` 按新意见更新方案，不触发空转上限 |
| A4 | 连续 3 次空 `reject` → `REVISION_EXHAUSTED`，无 Artifact |
| A5 | 「打开相机」→ 边界+建议，无插件 |
| A6 | 篡改字节 / 错误签名 / 危险 ZIP → 不激活，旧版仍在 |
| A7 | 已装纯本地插件断网可开，显示离线 |
| A8 | `autoLaunch=false` 时只安装不自动打开 |
| A9 | 杀进程后插件仍可发现并加载 |
| A10 | 第二个插件与第一个共存；更新失败保留旧 active |

## 5. 性能基线

含预览的正常任务 P95 ≤ 90s（不含人工等待）；压缩包 ≤ 10 MiB；端侧静态验证 P95 ≤ 2s。
