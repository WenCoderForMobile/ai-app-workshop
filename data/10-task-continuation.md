# 程序续作与历史修改

默认 APK 主 Agent 在理解需求时，由 LLM 返回 `taskRoute`：

| action | 示例 | 行为 |
| --- | --- | --- |
| continue | 继续之前失败的贪吃蛇 | 找到对应已确认任务，沿用原需求与源码直接续作 |
| modify | 给以前的贪吃蛇加音效 | 加载选定历史任务，保留原功能，确认新方案后修改源码 |
| new | 做一个独立的新贪吃蛇，旧的保留 | 创建独立任务与包名，不覆盖同名程序 |
| clarify | 改一下那个（目标不明确） | 澄清目标，不创建或修改程序 |

“继续并加音效”属于修改；没有确认过的草稿即使请求继续，也先确认方案。主 LLM 同时看到确切任务 ID、标题/摘要、原功能/验收、更新时间、构建和交付状态、失败原因、是否有可复用源码。目标 ID 必须匹配历史目录，不接受模型自造路径。

## 源码与进度

- 工作区：`out/tasks/<taskId>/dev/codex_work/`，各任务独立。
- 中断/失败草稿：`dev/source-draft/PluginMain.java`，不作为成功产物发布。
- 覆盖前的源码副本：`dev/source-checkpoints/<编号>/PluginMain.java`。
- 构建状态：`dev/build-state.json`，保存构建/运行修复状态及错误，重启后可读取。
- 生成状态：`dev/generation-state.json`，记录生成阶段及对应产品文档摘要。

已完成生成、需求未变的正式源码，续作时先重新编译；失败或中断的草稿先交编程 Agent 补全。编译失败继续在该源码上修复。需求变化会使旧的生成完成标记失效，不能把旧版本误当新需求已经完成。

对更新前遗留的共享 `out/codex_work/PluginMain.java`，只有源码包名与目标任务一致时才允许恢复；无法关联的草稿不会被盲目用于其他程序。

## 任务身份

taskId、包名、目录在任务创建后保持稳定。标题只是显示名称。独立新程序与旧程序同名时，任务 ID 添加后缀，不删除或重命名旧目录。生成 Agent 遵守主 Agent 选定的任务，不自行按标题相似度改写其他程序。

继续已确认任务不会重新覆盖确认文档；历史修改通过确认后更新同一任务的产品文档。已有源码一直保留，模型或 CLI 不可用时不会改造出一个名叫“继续”的新程序。

自动化测试使用模拟 LLM 决策与 CLI 输出，验证历史选择、失败重试、隔离工作区、草稿检查点、身份稳定及需求变更。没有发起真实模型续作或手机运行测试。重启 Python server 后生效，无需重编手机 APK。
